SOP MIGRASI: PHASE 1 & 2 (DATA EXTRACTION & STANDALONE SERVICE)

Foreign Key Detachment, CDC Replikasi via Kafka/Debezium, dan M2M Security Isolation
Database: PostgreSQL Standalone
Replikasi: Debezium + Apache Kafka
Halaman: 2 / 4 (Data & Service)
1. Detasemen Database & Foreign Key DATABASE ISOLATION
Langkah 1.1: Drop Physical Foreign Key Constraints
Hapus seluruh syntax CONSTRAINT fk_... FOREIGN KEY yang menghubungkan tabel target dengan modul luar.
Langkah 1.2: Pertahankan B-Tree Index
Ubah kolom relasi menjadi indeks performa: CREATE INDEX idx_boards_creator_id ON boards(created_by);.
Langkah 1.3: Logical Reference Architecture
Gunakan tipe data UUID murni. Integritas referensi divalidasi di layer aplikasi melalui Client, bukan database engine.
Transformasi Entitas JPA:
// SEBELUM: @ManyToOne User user;
// SESUDAH: @Column(name="user_id") UUID userId;
2. Pipeline Replikasi Data Realtime (CDC) CHANGE DATA CAPTURE
Tahap A: Skema & Initial Snapshot
Jalankan Flyway script pada DB baru. Debezium membaca WAL (Write-Ahead Log) PostgreSQL untuk initial bulk export historis.
Tahap B: Realtime Event Streaming (Kafka)
Setiap operasi INSERT/UPDATE/DELETE di DB Monolith dialirkan ke topik Kafka proms.cdc..events dalam format JSON.
Tahap C: Sinkronisasi Lag 0 Detik & Rekonsiliasi
Consumer di DB Standalone memproses stream event hingga Consumer Lag = 0 ms. Lakukan checklist hash rekonsiliasi data.
3. Scaffolding & M2M Security STANDALONE SETUP
1. Internal REST Contract Standard
Ekspos endpoint dengan prefix /api/v1/internal/.... Wajib menyediakan batch query /batch-lookup.
2. M2M Authentication (Internal Secret / mTLS)
Filter memvalidasi internal shared secret header X-Internal-Secret atau sertifikat mTLS antar pod Kubernetes.
3. Multi-Tenancy Context Filter
Membaca header X-Tenant-ID dan menginisialisasi TenantContext agar isolasi RLS tetap berjalan aman.
4. Health Check & Observability
Integrasi /actuator/health (Liveness/Readiness probe) dan registrasi OpenTelemetry tracing collector.
Logical Reference (No Physical FK)
Kafka + Debezium CDC
M2M Security + Multi-Tenancy Filter

SOP-ARCH-002

SOP MIGRASI: PHASE 3 (RESILIENT REMOTE CLIENT & DUAL-RUN)

Substitusi Spring RestClient, Resilience4j Fault Tolerance, dan Dual-Run Shadow Traffic
Client: Spring RestClient
Fault Tolerance: Resilience4j
Halaman: 3 / 4 (Resilient Integration)
1. Substitusi Zero-Rewrite di Monolith ADAPTER PATTERN
Kontrak Publik Abadi (Zero Changes):
Client.java (Interface) dan seluruh Record DTO di client/dto/ DILARANG DIUBAH. Modul pemanggil (seperti BoardService) tetap memanggil interface yang sama.
Implementasi Baru: <Feature>ClientRemoteImpl
Diletakkan di module//client/impl/ menggantikan in-memory class. Berkomunikasi via HTTP REST Client.
Dynamic Dual-Switch (Conditional Bean)
Gunakan konfigurasi @ConditionalOnProperty(name="proms.clients..mode") untuk switch instan in-memory vs remote.
2. Jaring Pengaman Jaringan (Resilience4j) FAULT TOLERANCE
1. Strict Timeouts (Peredam Thread Stalling)
Connect Timeout = 1000 ms, Read Timeout = 2500 ms. Cegah thread exhaustion pada Tomcat monolit.
2. Circuit Breaker (Auto-Isolation)
Jika kegagalan mencapai 50% dalam window 20 request, sirkuit OPEN selama 10s untuk melindungi microservice dari cascade failure.
3. Idempotent Retry Policy
Maksimal 2x retry hanya pada panggilan idempotent (GET/Batch Lookup) jika menerima status 503 atau connection drop.
4. Context Propagation Filter
RestClient menginjeksi header W3C traceparent dan X-Tenant-ID secara otomatis di setiap outbound HTTP call.
3. Dual-Run & Shadow Traffic Verification VERIFIKASI PRODUKSI
Mode Shadow Traffic (Dry Run)
Monolit mengeksekusi in-memory sebagai respons utama, dan secara asinkron (background) menduplikasi request ke remote service.
Auditor Perbandingan Respons (Diff Verifier)
Komparasi hash output antara in-memory vs remote response. Tingkat ketidakcocokan data (mismatch) harus 0.00%.
Profiling Beban Nyata (Load Soak Test)
Microservice baru menerima 100% trafik mirror selama 48 jam untuk mengukur p95/p99 latency sebelum traffic cutover sesungguhnya.
Target Kriteria Lulus Shadow:
  • Tingkat Error Remote < 0.01%
  • P95 Latensi Jaringan < 15 ms
  • Replikasi CDC Lag = 0 ms
Client Interface Zero Edit
Resilience4j Circuit Breaker
48-Hour Shadow Traffic Pass

SOP MIGRASI: PHASE 4 & 5 (CUTOVER, ROLLBACK & DECOMMISSIONING)

Staged Traffic Shifting, Emergency Instant Rollback (RTO < 60s), dan Final Clean Decommissioning
Rollback Target: RTO < 60 Detik
Observasi: 14 Hari Produksi
Halaman: 4 / 4 (Cutover & Cleanup)
1. Matriks Tahapan Traffic Shifting CUTOVER PIPELINE
Stage 1: Canary 10% (Read-Only)
10% query pembacaan dialihkan ke remote service via Feature Flag. Pantau log error Sentry & Prometheus selama 24 jam.
Stage 2: 50% -> 100% Read Traffic
Pindahkan seluruh operasi read ke remote. Database Monolith tetap menjadi master penulisan (CDC terus mereplikasi).
Stage 3: Write Cutover & Reverse CDC
Alihkan seluruh operasi create/update ke microservice baru. Balik arah sinkronisasi CDC (DB Microservice → DB Monolith) sebagai jaring pengaman rollback!
Jaring Pengaman Reverse CDC:
Dengan menyinkronkan data kembali ke DB Monolith, jika terjadi kegagalan darurat, monolit memiliki data mutakhir dan siap mengambil alih trafik seketika.
2. SOP Rollback Darurat (RTO < 60s) FAILSAFE PROTOCOL
Kondisi Pemicu Rollback Darurat:
  • Lonjakan HTTP 5xx > 1% dalam 5 menit
  • P99 latency melonjak > 2500 ms (Circuit Breaker OPEN)
  • Inkonsistensi data transaksi finansial/state critical
Langkah 1: Saklar Runtime Config (10 Detik)
Ubah konfigurasi runtime via Spring Cloud Config / Consul tanpa redeploy: proms.clients..mode=in-memory.
Langkah 2: Verifikasi Aliran Trafik (20 Detik)
Trafik otomatis kembali ditangani oleh in-memory bean. Pastikan error rate langsung turun kembali ke nol.
Langkah 3: Audit Integritas Data (30 Detik)
Verifikasi data transaksi terakhir dari reverse CDC telah tersimpan utuh di DB Monolith. Matikan service remote untuk diinvestigasi.
3. Decommissioning & Definition of Done PEMBERSIHAN TOTAL
Syarat Decommissioning: Sistem microservice baru telah berjalan stabil di produksi selama minimal 14 hari tanpa insiden P1/P2.
1. Hapus Internal Domain di Monolith
Hapus folder module/// (service, repository, entity, controller). Hapus class ClientImpl.java.
2. Kunci Remote Client Sebagai Permanen
Hapus flag conditional. Jadikan ClientRemoteImpl.java sebagai satu-satunya bean resmi implementasi.
3. Drop Tabel di Database Monolith
Jalankan Flyway migration baru untuk mendrop tabel lama di database monolit. Matikan konektor CDC dan topik Kafka.
4. Update Dokumentasi & Sign-Off
Perbarui Architecture Map, perbarui ArchUnit test suite, dan tandatangani serah terima sistem ke squad owner.
Canary Shifting (10% → 50% → 100%)
Emergency Rollback (RTO < 60s)
14-Day Stable Decommissioning
